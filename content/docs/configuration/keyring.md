**Placement:** `server -> keyring`

The `keyring` block (Norca) configures the seal of the server's keyring: the root keys that encrypt
Variables and sign workload identities, and the key of the built-in secret store, are wrapped by the seal
on disk. See [Seal](/docs/features/secrets/seal) and [Operating the seal](/docs/operations/seal-unseal).

```hcl
server {
  keyring {
    seal "shares" {
      shares    = 5
      threshold = 3
    }
  }
}
```

Without a `keyring` block, the server uses the `aead` seal: the key-encrypting key is stored next to the
key, as in Nomad v1.6.5. The agent logs a warning; use `aead` for development and migration only.

Configuring `seal "shares"` does not convert an existing keyring by itself. A new region stays
uninitialized and a region that already has keys keeps its current seal until
[`norca operator keyring rewrap -to shares`](/docs/commands/operator/keyring-rewrap) runs. All servers of a
region should have the same `keyring` block.

## `keyring` Parameters

- `seal` <code>([seal](#seal-parameters): nil)</code> - The seal. The block label is the seal type,
  `shares` or `aead`. Only one `seal` block can be given. The types `awskms`, `gcpckms`, `scwkms` and
  `transit` are reserved for later and rejected with "not implemented yet".

### `seal` Parameters

- `shares` `(int: 5)` - For `seal "shares"`: the number of unseal shares generated by the first rewrap to
  `shares`. Between 2 and 255.

- `threshold` `(int: 3)` - For `seal "shares"`: the number of distinct shares that unseal a server.
  Between 2 and `shares`; the default is 3, or `shares` if that is smaller.

The `aead` seal has no parameters.

The values are defaults for [`norca operator keyring rewrap`](/docs/commands/operator/keyring-rewrap),
whose `-shares` and `-threshold` flags override them. After the shares exist, the threshold recorded with
the seal of the region applies.

## `keyring` Examples

### Development (explicit `aead`)

```hcl
server {
  keyring {
    seal "aead" {}
  }
}
```

### Production

```hcl
server {
  keyring {
    seal "shares" {
      shares    = 5
      threshold = 3
    }
  }
}
```

Check the configuration with `norca config validate`, which validates the `keyring` block as the agent
does when it starts.
